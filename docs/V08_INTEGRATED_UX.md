# v0.8 모바일·태블릿 통합 UX

사용자가 검토한 10개 상태 목업과 제스처 시작 영역 제한을 구현한다. PR #4 개발 브랜치에서 작업하며 공식 main/PR #3은 변경하지 않는다. 기존 엔진·생태계·실험 덱/목표·60도 회전·저장 v3는 그대로다.

## 현재 입력

| 입력 | 실제 동작 |
|---|---|
| 배치 가능한 빈 칸 짧은 탭 | 드래프트 전체 3D 타일 선택 + 약 260ms 구도 이동 |
| 다른 빈 칸 탭 | 기존 모델 제거, 같은 회전 방향으로 즉시 이동, 새 연결·예상 별 계산 |
| 현재 미리보기 칸 재탭 | 지연 없이 확정. 이때만 엔진의 타일/별/생태 진행 변경 |
| 놓인 타일/배치 불가능한 빈 배경 단일 탭 | 약 240ms 뒤 미리보기 취소 |
| 같은 배경 근처 더블탭 후 두 번째 터치 유지 | 좌우 카메라 orbit, 위로 드래그 확대/아래로 축소. 회전·줌 기호만 잠시 표시 |
| 단순한 배경 더블탭 | 카메라 변화/배치/미리보기 취소 없음 |
| 약 400ms 롱프레스 + 좌우 이동 | 기존 36px당 60도 타일 회전, 반전 8px 히스테리시스 |
| 처음부터 이동이 8px을 넘음 | 기존 한 손가락 팬. 롱프레스/탭 판정 제외 |
| 두 손가락 핀치 | 확대·축소, 중심 이동 팬. 자동 배치 없음 |
| 회전·카메라 조작에서 손 떼기 | 현재 드래프트 유지. 자동 배치 없음 |
| PC | 기존 좌클릭 orbit, 우클릭/Shift 팬, 휠 줌, 회전/확정 버튼 유지 |

카메라는 **놓인 타일 또는 배치 불가능한 빈 배경**에서만 시작한다. 새 빈 칸이나 현재 미리보기는 타일 조작이 우선이다. 이 제한은 목업 검토 시 승인된 정책이다. 더블탭 후보는 약 240ms/24px이며 두 번째 hold는 약 150ms 또는 8px 이동으로 활성화한다. 모두 입력 실험값이며 실기기 감도 피드백에 따라 조절할 수 있다.

배경 단일 탭 취소만 짧게 보류하고 빈 칸 선택/이동/확정은 기다리지 않는다. 두 번째 touch가 카메라 후보가 되면 예정된 취소를 제거한다. 드래그/멀티터치/취소/화면 방향 변경/blur/백그라운드 전환은 타이머와 입력 잠금을 정리한다. 활성 회전의 pointercancel은 기존 안전 정책으로 미리보기를 취소한다. 카메라 취소는 드래프트를 배치하지 않고 종료한다.

메뉴/도움말은 미리보기를 유지한 채 입력을 멈춘다. 2D/3D 보기 전환이나 실제 포기는 미확정 미리보기만 정리한다. 메뉴 입력이 보드의 취소 탭으로 전달되지 않는다.

## 들기와 회전 표현

인식기는 재작성하지 않고 기존 경로에 카메라 중재 상태를 더했다. PreviewMotion이 렌더링 상태만 관리한다.

- 선택 외곽은 차분한 얇은 선이며 일치 면 표시·예상 별은 엔진 예측을 사용한다.
- 400ms 인식 후 약 120ms 동안 7% 확대/0.06 반경만큼 들고, 다음 120ms 동안 3% 확대/0.04 높이로 안정화한다. 바닥 footprint는 고정되어 작은 틈이 보인다. shadow map은 켜지 않는다.
- 60도 회전마다 약 90ms 시각 보간을 하고 연결·별 계산은 즉시 갱신한다. 입력을 연출 종료까지 기다리거나 애니메이션 큐를 쌓지 않는다.
- 손 떼면 약 120ms 안에 기본 크기와 높이로 돌아가며 마지막 드래프트 방향은 유지한다.
- reduced-motion은 확대/들기/회전 보간을 생략하고 기호와 외곽으로 상태를 알린다.

## 화면과 카메라

모바일 상시 조작은 우상단 메뉴 1개다. 줌±/중심/회전/확정/취소/undo/재시작 버튼은 게임판에서 숨긴다. 메뉴 안에 계속 플레이, 2D/3D 전환, 도움말, 실험 설정, 포기를 모았다. 목표 두 개와 남은 타일·다음 타일은 읽기 전용 정보다. 다음 타일 미니어처는 기존 Canvas 표현을 보존했으며 목업의 입체 썸네일과는 차이가 있다.

실제 HUD/다음 타일/예측 정보/안전 영역을 제외한 구도를 사용한다. 6개 인접 칸의 투영을 고려하고 필요할 때만 최소 줌아웃한다. 카메라 azimuth는 바꾸지 않는다. 새 pointerdown은 자동 구도를 중단해 롱프레스 중 타일이 손가락 밑에서 움직이지 않는다.

전략적 보기는 같은 3D scene이다. 정규화 시야 지표 `distance * sqrt(min(1, aspect))`가 24를 넘으면 진입, 20 미만이면 복귀한다. 고도는 약 240ms에 1.22rad로 높아지고 풍경 복귀 시 이전 사선 고도로 돌아온다. 방위각·게임 규칙은 같다. terrain 외곽/빈 칸 대비를 높이고 먼 바위/산 장식만 숨긴다. 나무·집·물·수달은 같은 모델을 쓴다. 작은 ‘전략’ 표시가 있고 별도 전환 버튼은 없다. 수동 orbit은 자동 고도 보간을 중단한다. 이 임계값도 실험값이다.

팬 범위는 보드+available frontier의 월드 AABB와 현재 카메라의 보드 평면 투영 footprint로 계산한다. 줌/방위각/화면 비율과 맵 성장에 따라 여백이 변한다. 경계에서 저항을 높이고 손을 떼면 약 140ms에 안정화한다. 고정 픽셀로 맵 크기를 제한하거나 타일 공급을 바꾸지 않는다. 극소 분할 화면/열린 메뉴에서는 주변 6칸 전체 가시성을 보장하지 않는다.

## 메인·포기·보기 전환·저장

처음에는 HEX HAVEN 메인이 나오며 기존 활성 저장이 있다면 이어하기가 표시된다. 이미 플레이 중이던 활성 시도는 새로고침·재접속 시 계속한다. ‘스테이지 시작’은 기존 일반 스테이지 1, ‘실험 모드’는 기존 Comfort/Standard/Challenge와 시드 입력으로 이어진다. 새 시도가 활성 저장을 대체하면 먼저 확인한다. 새 해금·보상·등급은 없다.

스테이지 포기 확인창에서 ‘계속 플레이’는 게임으로 돌아간다. ‘포기하고 나가기’는 해당 시도를 abandoned로 기록하고 메인으로 간다. 엔진의 Pass/Fail과 섞지 않는다. 완료된 게임에서 나가기는 Pass/Fail을 유지한다. 예전 재시작 버튼은 모바일/일반 메뉴에서 사용하지 않는다.

`session-state.js`는 UI 세션 metadata version 1의 active/abandoned/passed/failed/idle을 담당한다. 게임의 version 3 데이터 형식은 바꾸지 않는다. metadata가 없는 이전 저장은 engine.status에서 상태를 파생하고 기존 덱/좌표/별/시드를 그대로 읽는다. 포기 후 일반 이어하기·새로고침·다른 탭·2D 전환으로 같은 시도를 부활시키지 않는다. 엔진 snapshot/history는 내부 복구를 위해 보존한다.

2D와 3D는 같은 저장 슬롯과 세션 metadata를 사용하고 양방향 메뉴 링크가 있다. 전환은 새 게임을 만들지 않는다. 테스트는 스냅샷 전체(시드/난이도/덱/회전/index/별/타일/생태/metrics)를 비교한다. 2D는 보조 보기이므로 기존 버튼 조작이다.

일반 undo는 계속 막는다. `?testUndo=1`은 메뉴에서 복구 버튼을 노출하는 테스트 플래그이며 게임 엔진의 undo/history를 유지한다. `?play=1`은 새 idle/기존 시도의 UI 회귀 검사 진입용이며 abandoned는 되살리지 않는다. 클라이언트 저장과 플래그는 보안 경계가 아니다. 이전 데이터 수동 주입·개발자 도구까지 막는 경쟁 게임 정책을 도입하지 않는다.

## Safari 선택 방지와 안내

실제 `#board` 및 입력을 받지 않는 보드 장식만 user-select/-webkit-user-select:none, -webkit-touch-callout:none, touch-action:none을 쓴다. canvas의 contextmenu/selectstart/dragstart는 cancelable일 때만 preventDefault하고 리스너는 passive:false다. body 전체의 선택을 막지 않는다. 시드 input·설정·메뉴·결과 textarea의 텍스트 입력과 선택은 유지한다.

기본 ‘빈 칸 터치 · 드래그로 이동’, 선택 시 ‘길게 눌러 회전 / 다시 탭 배치 / 빈 칸 이동 / 바깥 취소’, 회전 중 ↶↷, 카메라 중 ↔회전·↕줌을 작은 크기로 표시한다. 성공 배치 경험을 UI 설정에 기록해 이후 기본 안내를 줄인다. 메뉴 도움말에서 다시 확인할 수 있다. 수달 발견은 기존 요청 문구·3초 종료·X 닫기·중복 방지를 유지하며 2D도 같은 알림 규칙을 사용한다.

## 검증·한계

자동/브라우저 결과는 V08_INTEGRATED_RESULTS.json을 참조한다. 기존 엔진·생태계·난이도 파일은 기준 ZIP과 바이트 단위로 동일하다. 검토된 목업은 화면 구성을 위한 합성 이미지이며 실제 보드 배치·점수·동물 수는 저장된 게임 진행을 따른다. 실제 화면은 테스트가 생성한 Chromium 캡처이며 목업과 구분한다.

실제 iPhone/iPad Safari·Android 기기는 별도로 확인해야 한다. 특히 iPad의 파란 텍스트 선택 강조가 사라졌는지는 Linux WebKit/Chromium 검사만으로 실기기 완료라고 하지 않는다. 주소창 높이·안전 영역·손가락 속도/떨림·장시간 발열·앱 복귀도 미검증이다. 소프트웨어 GPU 성능은 모바일 하드웨어 수치가 아니다. 전체 덱의 해답과 undo 없는 난이도 밸런스는 계속 미확정이다.

배포 도구는 요청된 `current/` 경로와 `hexhaven-preview:pr-4-integrated:` 저장 접두사를 사용한다. 이전 main/PR #3 및 기존 미리보기 경로·저장을 보존한다. source SHA는 preview.json/페이지 제목/메뉴 버전에 표시하고 상대 모듈·CSS에 같은 버전을 붙인다. HTTPS 접속·파일 해시·공개 버전 실행을 확인한 후 URL을 보고한다.
